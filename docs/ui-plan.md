# 大会運営アプリ UI・デザイン改善計画

Oct 18, 2026 · @びび

## 前提

結論：配色の変数・タブ構成・呼び出し画面などの土台はすでに整っています。作り直しではなく「スマホでの結果入力」「表の見やすさ」「設定画面の流れ」の3点を重点的に直すのが効率的です。

確認した範囲：リポジトリの README.md・CLAUDE.md・TODO.md・web/style.css・src/render/svg.js を読み、手元でビルドして PC（幅1280px）とスマホ（幅390px）で12人のトーナメント・総当たりを作って画面を確認しました。公開ページも同じ画面構成（ヘッダー：新規／保存／読込／印刷／共有、タブ：参加者・設定／トーナメント／総当たり／順位表）です。

想定：部活などの部内大会（卓を使う競技）で、運営者1人が入力し、参加者はスマホで閲覧する使い方。外部公開の大規模大会向けではないと見ています。違う場合は優先度が変わります。

### AIに渡すときの共通ルール

各指示の先頭に、次の文をそのまま付けてください。

```markdown
作業前にリポジトリの CLAUDE.md を読み、その規約に従ってください（実行時ライブラリは0個のまま、ロジックは src/core、画面の文言は日本語）。
既存の id・data-act・data-tab 属性は E2E テストが使っているので変えないでください。変える場合はテストも直してください。
画面の色やフォントを変えたら、PNG出力（src/render/svg.js）と印刷（web/style.css の @media print）も同じ見た目にそろえてください。
完了条件：npm run build・npm test・npm run test:e2e がすべて成功し、幅390pxと1280pxのスクリーンショットで崩れがないことを確認し、CHANGELOG.md と TODO.md を更新すること。
```

1回の依頼は1〜2項目にしてください。まとめて頼むと、テストが壊れたときに原因を追えなくなります。

## ① 参考ソフトの分析

結論：取り入れる価値が高いのは「確定前に組み合わせを確認・入れ替える段階」（Tonamel）、「卓ごとの割り当てと呼び出し」（start.gg）、「入力しながら表を即プレビュー」（THE TOURNAMENT）の3つです。どれも既存機能の延長で実装できます。

| ソフト | 概要 | UI・設計で参考になる点 | このアプリへの生かし方 |
| --- | --- | --- | --- |
| [Tonamel](https://tonamel.com/help/create-brackets) | 国内のゲーム大会プラットフォーム | 作成が「対戦数（勝利条件）の設定 → 組み合わせ設定 → 大会開始の確認 → 確定」の段階式。確定前に対戦相手を個別に入れ替えたり、全体をシャッフルしたりできる | 設定画面を段階表示にする（D5）。表の作成前に組み合わせを確認・入れ替える画面を挟む（F4） |
| [Tonamel（参加方法）](https://tonamel.com/help/how-to-participate) | 同上 | チェックインがあり、会場ではQRコードを受付が読み取る方式も選べる | 当日の出欠確認（F3）。欠席者をその場で不戦にできる |
| [start.gg](https://help.start.gg/en/articles/13766148-assigning-stations) | 海外の大規模ゲーム大会向け | 試合ごとに「ステーション（卓）」を割り当てる。表の上で試合にカーソルを当ててアイコンから割り当てる。空いた卓へ自動で割り当て続け、同時に試合を呼び出す設定もある。卓をグループでまとめて管理できる（[Stations and Streams](https://help.start.gg/article/streams-and-stations)） | 卓の空き状況を見える化し、空いた卓に次の試合を出す（F2）。呼び出し画面と連動させる |
| [Challonge](https://wordpress.org/plugins/challonge/) | 海外の定番トーナメント作成サービス | シングル・ダブルイリミネーション、総当たり、スイス式に対応し、総当たりとスイス式は順位表を表示する。参加者が自分でスコアを報告できる設定がある | 閲覧者からの結果報告（運営が承認して反映）（F8）。形式の追加は今回は見送り |
| [THE TOURNAMENT](https://gigazine.net/news/20180805-the-tournament) | 国内の無料トーナメント表作成サービス | 参加者を1行1チームで入力すると、右側にトーナメント表がその場で表示される。勝者はラジオボタン、スコアは名前の横の欄に入れる。全試合が終わると優勝を金、準優勝を銀で強調する。共有URLと画像の出力がある | 作成前に表の組み合わせを見せる（F4）。大会終了時の表彰表示（D11） |

どのソフトにも共通する作りは、運営者が「今どの試合をどこでやるか」を1画面で判断できることです。このアプリはすでに「次に行う試合」と「呼び出し画面」を持っているので、ここを中心に磨くのが効果的です。

## ② デザイン改善案

結論：最優先はスマホで結果を入力・確認する画面（D1〜D3）です。当日いちばん触る画面なのに、今いちばん崩れています。配色は今の紺と青を残し、色の管理を1か所にまとめる（D6）だけで十分です。

難しさの目安：易＝CSSと少しの修正で1回の依頼、中＝画面の組み替えで1〜2回、難＝表示の仕組みから変えるので2回以上。

| ID | 改善項目 | 対応する問題 | 優先度 | 難しさ |
| --- | --- | --- | --- | --- |
| D1 | スマホの結果入力を縦並びのシートにする | P1 | 高 | 易 |
| D2 | スマホのヘッダーを1段にし、タブを画面下に固定する | P2 | 高 | 中 |
| D3 | 試合結果一覧をスマホではカード表示にする | P3 | 高 | 中 |
| D4 | トーナメント表の見せ方（全体表示・拡大縮小・回戦ごとの表示） | P4 | 高 | 難 |
| D5 | 参加者・設定を3段階の流れにする | P6・P9 | 中 | 中 |
| D6 | 色を1か所で管理し、画面・PNG・印刷でそろえる | P5 | 中 | 易 |
| D7 | 試合の状態をバッジと記号で示す（色だけに頼らない） | P5・P8 | 中 | 易 |
| D8 | 順位表の並び順と勝ち残りの表示 | P7 | 中 | 易 |

### D1 スマホの結果入力を縦並びのシートにする（高・易）

```markdown
結果入力ダイアログ（web/index.html の #result-dialog、src/ui/resultDialog.js、web/style.css の .rd-* と dialog）を、画面幅600px以下で次のように変えてください。PCの見た目は変えません。
- ダイアログを画面下から出るシートにする（幅100%、上の角だけ丸く、max-height: 90dvh、中身はスクロール）。
- 「選手1の行（ラジオ・名前・スコア欄）」「－」「選手2の行」を縦に積む。名前は横書き1行で表示し、1文字ずつ縦に折り返さないこと。
- 選手の行全体をタップすると勝者になる。選んだ行は左に4pxの線と「勝者」の文字バッジを付ける（色だけで示さない）。
- スコア欄は幅72px以上・高さ48px以上、文字20px。inputmode="numeric" はそのまま。
- ボタンはシートの下に固定する。1段目「キャンセル」「保存して次へ」を横並び、2段目「保存」を全幅の主ボタン、最下部に「結果を取り消す」を文字だけのボタンで置く。どのボタンも文字を折り返さない（white-space: nowrap）。
- 不戦勝・引き分け・卓の選択は、スコアの下に1行ずつ並べる。
- 既存の id（rd-p1, rd-p2, rd-s1, rd-s2, rd-ok, rd-next, rd-cancel, rd-clear, rd-table, rd-walkover）と name="outcome" は変えない。
確認：幅390pxで、選手名「渡辺 五郎」と「ああああああああああ」（10文字）の試合を開き、スクリーンショットで名前が横書きで読めること、ボタン文字が1行に収まることを確かめる。
```

### D2 スマホのヘッダーを1段にし、タブを画面下に固定する（高・中）

```markdown
画面幅700px以下のヘッダーとタブ（web/index.html の .app-header と nav.tabs、web/style.css）を次のように変えてください。PCは今のままにします。
- ヘッダーは1段（高さ52px程度）にする。左にアプリ名（長いときは省略記号で切る）、右に自動保存の状態（「保存済み」など短い表記）と「メニュー」ボタン（三本線のアイコン＋aria-label="メニュー"）だけを置く。
- 「新規」「保存」「読込」「印刷」「共有」はメニューを開いたときの縦並びリストに移す。各行は高さ48px、ボタンの data-action 属性はそのまま使う。
- タブ（参加者・設定／トーナメント／総当たり／順位表／コメント）は画面下に固定したタブバーにする。各タブは文字＋簡単なアイコン（SVGを直接書く。ライブラリは使わない）で、高さ56px以上、iPhoneの下の余白（env(safe-area-inset-bottom)）を空ける。
- 本文の下に、タブバーと同じ高さの余白を付けて、最後の行が隠れないようにする。
- 閲覧者（body.viewer）では「参加者・設定」タブを出さない今の動きを保つ。
- role="tab"、aria-selected、data-tab 属性は今のまま。
確認：幅390pxで全タブを順に開き、タブが見切れず1画面に収まること、メニューからすべての操作ができることを確かめる。
```

### D3 試合結果一覧をスマホではカード表示にする（高・中）

```markdown
トーナメント・総当たりの「試合結果一覧」（table.data.results）を、画面幅700px以下ではカードの縦リストで表示してください。PCは表のままです。
- 1試合を1枚のカードにする。1行目に「No.番号・回戦・卓・時間帯」を小さく、2行目に「選手1 スコア － スコア 選手2」を大きく、勝者の名前を太字にする。右上に状態のバッジ（D7）を置く。
- 不戦の行は1行に縮める（例：「山田 太郎　不戦で勝ち上がり」）。
- カードをタップすると今の行のクリックと同じく結果入力が開く。
- 方法は、同じデータからカード用のHTMLも出力し、CSSのメディアクエリで表とカードを切り替える。CSV・PNG出力は今の表データ（src/core/exportData.js）から作り続け、変えない。
確認：幅390pxで12人のトーナメントと総当たりの一覧を表示し、横スクロールが出ないことを確かめる。
```

### D4 トーナメント表の見せ方（高・難）

```markdown
トーナメント表の表示（src/ui/tournamentView.js、web/style.css の .bracket-wrap）を次のように変えてください。PNG出力と印刷の見た目は変えません。
- .bracket-wrap の max-height による枠内の縦スクロールをやめ、縦はページのスクロールに任せる。横は枠内スクロールのままにする。
- 表の上に操作バーを置く：「全体表示」（枠の幅に収まるよう縮小）、「－」「＋」（50%〜150%、25%刻み）、回戦名のボタン（1回戦・準々決勝…。押すとその回戦の列まで横にスクロール）。拡大率は SVG の width/height を変えて実現し、ライブラリは使わない。
- 画面幅700px以下では、初期表示を「回戦ごと」表示にする。回戦名のタブを横に並べ、選んだ回戦の試合をカード（選手2人・スコア・卓・状態）で縦に並べる。「表で見る」に切り替えると今のSVGの表になる。
- どちらの表示でも、試合を押すと今と同じく結果入力が開く。
- 「次に行う試合」をクリックしたときと、結果を保存したあとは、その試合がある位置までスクロールし、試合の枠を1.5秒強調する（prefers-reduced-motion のときは強調だけで動きなし）。
確認：12人・32人・64人で、幅1280pxでは「全体表示」で決勝まで見えること、幅390pxでは回戦ごとの表示で横スクロールが出ないことを確かめる。
```

### D5 参加者・設定を3段階の流れにする（中・中）

```markdown
「参加者・設定」タブ（src/ui/setupView.js、src/ui/editions.js、web/style.css）の並びと見せ方を次のように変えてください。設定の中身と保存形式は変えません。
- タブの最上部に3段階の表示を置く：「1 大会情報と参加者」「2 卓と形式」「3 表を作成」。各段階は押すとその位置へスクロールする。参加者が2人以上いれば1に、作成済みなら3にチェック印を付ける。
- カードの順番を「大会情報 → 参加者 → 卓 → トーナメント → 総当たり → 大会の回数」にする。「大会の回数」は過去の大会が0件のときは折りたたみ（details 要素）にし、見出しだけ見せる。
- PC（幅900px超）は左列に「大会情報・参加者」、右列に「卓・トーナメント・総当たり」を置く今の2列を保つ。
- 「トーナメント表を作成」「総当たり表を作成」の主ボタンは、各カードの下で全幅にする。作成済みのときは文言を「作り直す」にし、結果が消えることを1行で添える。
- 幅700px以下の崩れを直す：開催日時は日付と時刻を2列で横に並べる。勝点の「勝・分・敗」は3列の格子で1行に収める。参加者の見出し行は「一括入力・CSV取込」「全員削除」を見出しの下の1行に並べる。
確認：幅390pxと1280pxで、参加者0人・12人・作成済みの3状態をスクリーンショットで確かめる。
```

### D6 色を1か所で管理し、画面・PNG・印刷でそろえる（中・易）

```markdown
色の値を1か所にまとめてください。
- src/render/theme.js を新しく作り、色の定数をまとめて export する。値は今の web/style.css の :root の変数（--ink #13233a、--primary #1d5fbf、--gold #8a5a00 など）に合わせる。
- src/render/svg.js の定数 C を theme.js の値に置き換える。勝ち上がりの線と勝者の枠は赤（#c62828）のまま残す（日本のトーナメント表で一般的な表し方のため）。試合待ちの番号の青は --primary と同じ値にする。
- 赤を使う場所を「トーナメント表の勝ち上がり線」と「削除・エラー」の2つに限る。結果入力で選んだ勝者の行（.rd-player:has(input:checked)）は赤ではなく、--primary の枠と --primary-weak の背景にする。
- web/style.css の :root と theme.js の値が一致しているかを確かめる単体テストを test/unit に追加する。
確認：画面・PNG出力・印刷プレビューで、トーナメント表と総当たり表の色が同じになっていること。
```

### D7 試合の状態をバッジと記号で示す（中・易）

### D9 総当たりの試合一覧に絞り込みを付ける（中・中）

### D10 操作感の細部（中・易）

```markdown
次の細かな操作感を直してください。
```

### F1 閲覧者が「自分の試合」を探せる（高・易〜中）

```markdown
共有の閲覧者（body.viewer）向けに「自分の試合」機能を追加してください。
- 閲覧画面の上部に「名前を選ぶ」欄（参加者名の選択肢、文字入力で絞り込み）を置く。選んだ名前はこの端末の localStorage に保存する（try/catch で囲む）。
- 名前を選ぶと上部に「あなたの次の試合」カードを出す：卓名・時間帯・対戦相手・試合番号。試合がなければ「次の試合は未定です」または「全試合が終わりました（成績：〇勝〇敗／ベスト8 など）」。
- トーナメント表・総当たり表・試合結果一覧では、その選手の名前を太字＋背景色で強調する。
- 運営の画面にも同じ機能を付けるが、初期状態はオフにする。
- 判定などのロジックは src/core に置き、単体テストを追加する。
```

### F2 試合の「開始」と卓の空き状況（高・中）

```markdown
試合に「進行中」の状態と、卓の空き状況の表示を追加してください。
- 大会データ（src/core/state.js）の試合に startedAt（開始時刻、ISO文字列、未開始は null）を追加する。古い保存データは null として読み込めるよう移行処理と単体テストを追加する。
- 「次に行う試合」のカードに「開始」ボタンを付ける。押すと進行中になり、カードに経過時間（分）を表示する。結果を保存すると進行中は終わる。開始の取り消しもできる。
- 進行状況の欄に卓の一覧を出す：卓ごとに「空き」または「進行中：No.5 山田 太郎 vs 中村 六郎（12分）」。空いた卓には、その卓に割り当てられた次の試合を「次」として出す。
- 呼び出し画面にも「進行中」と「次」を分けて表示する。
- 状態のバッジ（改善案D7）に「進行中」を加える（--ok の緑の塗り）。
- 共有している場合、閲覧者にも進行中が見えること。
```

### F3 当日の出欠確認（中・中）

```markdown
参加者名簿に出欠の欄を追加してください。
- 名簿の各行に「出席」チェックを付ける（初期値は全員出席）。上部に「出席 10 / 12人」と「全員出席にする」ボタンを置く。
- 表の作成前なら、欠席者を除いて表を作るか、欠席者を入れたまま不戦にするかを、作成時の確認画面で選べるようにする。
- 作成後に欠席にした場合は、その選手の未実施の試合を不戦（相手の不戦勝）にするかを確認してから反映する。今の不戦勝の仕組み（result.walkover）を使う。
- 出欠は大会データに保存し、古いデータは全員出席として読み込む。
```

### F4 作成前に組み合わせを確認・入れ替える（中・中〜難）

```markdown
トーナメント表を作成する前に、組み合わせを確認する画面を挟んでください（TODO.md の「シード：抽選結果を先に表示して確認・やり直し」と「組み合わせのドラッグ編集」を兼ねる）。
- 「トーナメント表を作成」を押すと、1回戦の組み合わせ一覧（試合番号・選手1・選手2・卓）を表示するダイアログを出す。
- 「抽選をやり直す」（シード・配置がランダムのとき）、2人の選手を順に選んで位置を入れ替える「入れ替え」、「この組み合わせで作成」「キャンセル」を置く。ドラッグは使わず、タップ2回で入れ替える（スマホで確実に操作できるため）。
- 確定するまで大会データは変えない。入れ替えは src/core/bracket.js の配置を作る関数に「指定した配置」を渡せるようにして実現し、単体テストを追加する。
```

### F5 元に戻す（中・中）

```markdown
直前の操作を取り消す「元に戻す」を追加してください。
- 大会データは core の関数で新しい値に置き換える作りなので、src/ui/store.js で置き換える前の値を最大20件の履歴として持つ。
- ヘッダー（スマホはメニュー内）に「元に戻す」ボタンを置き、Ctrl+Z でも動くようにする。入力欄にフォーカスがあるときの Ctrl+Z は文字入力の取り消しを優先する。
- 結果の保存・取り消し、参加者の追加・削除・並べ替え、表の作成は戻せる。共有中は、戻した内容も今と同じ仕組みで送信する。
- 履歴はページを再読み込みすると消えてよい。過去の大会を閲覧中は使えないようにする。
```

### F6 初回の「サンプルで試す」と短い使い方（中・易）

### 進め方

この計画書をMarkdownで書き出し、リポジトリに docs/ui-plan.md として置いてください。毎回の依頼は次の形で短く済みます。

```markdown
docs/ui-plan.md の「D1」を実装してください。
作業前にリポジトリの CLAUDE.md を読み、その規約に従ってください（実行時ライブラリは0個のまま、ロジックは src/core、画面の文言は日本語）。
既存の id・data-act・data-tab 属性は E2E テストが使っているので変えないでください。変える場合はテストも直してください。
画面の色やフォントを変えたら、PNG出力（src/render/svg.js）と印刷（web/style.css の @media print）も同じ見た目にそろえてください。
完了条件：npm run build・npm test・npm run test:e2e がすべて成功し、幅390pxと1280pxのスクリーンショットで崩れがないことを確認し、CHANGELOG.md と TODO.md を更新すること。
```

コードを細かく読まなくても、確認はPRのスクリーンショットと、PRごとに作られる共有サーバーのプレビュー（README の Workers Builds の項）を自分のスマホで開くことでできます。とくに D1・D2・D3 は、実際のスマホで1試合入力してみてから次へ進んでください。
