### N1 本番環境と実機での確認（高・易）

これはAIではなく自分で行います。AIの確認は Chromium の模擬だけなので、本番でしか分からない不具合が残っていても気づけません。実際の大会の前に、部員数人で模擬大会を開くのがいちばん確実です。

- [ ] 公開ページで「共有」を始め、別のスマホで閲覧リンクを開く（QRコードの読み取りも試す）
- [ ] 運営が結果を入れて、閲覧者の画面に15秒以内に出るか
- [ ] 閲覧者から結果を報告し、運営が承認して表に反映されるか（F8）
- [ ] 「開始」を押し、閲覧者の画面で「進行中」と経過時間が出るか（F2）
- [ ] iPhone の Safari で結果入力シートを開き、キーボードを出しても「保存」が押せるか（D1）
- [ ] iPhone の Safari で上に固定したタブが、アドレスバーの出入りでずれないか（D2）
- [ ] 開催日時の入力欄が iPhone と Android で使えるか
- [ ] 呼び出し画面をプロジェクターか大きな画面に映し、会場の後ろから読めるか
- [ ] Windows の PC で .exe を起動し、フォントが IBM Plex になっているか
- [ ] トーナメント表と順位表を紙に印刷する

不具合が見つかったら、次の形で頼みます。

```markdown
実機で次の不具合を見つけました。端末：（例：iPhone 13、iOS 18、Safari）。手順：（押した順に）。起きたこと：（画面の様子）。期待したこと：（本来の動き）。スクリーンショットを添付します。
原因を調べて直し、再発を検出するテストを足してください。TODO.md の「未検証」の該当する行を、確認した結果に合わせて書き換えてください。
```

問題がなかった項目も、「TODO.md の未検証から、iPhone Safari での D1 の確認を『確認済み（日付・端末）』に移してください」と頼んで記録を残してください。

### N3 スマホの総当たりを「回戦ごと」表示にする（高・中）（実装済み）

```markdown
「総当たり」タブ（src/ui/leagueView.js）を、画面幅700px以下で次のように変えてください。PCは今のままです。
現状：12人の総当たりで、幅390pxのページの高さが約7,800px。対戦表（マトリクス）は幅約1,250pxを幅約330pxの枠で横にスクロールさせている。試合結果一覧は66枚のカードがすべて並ぶ。
- トーナメントのスマホ表示（src/ui/roundView.js）と同じ形で、「回戦ごと」／「対戦表で見る」の切り替えを置き、初期表示を「回戦ごと」にする。
- 「回戦ごと」では、回戦のタブ（1回戦〜11回戦）を横に並べ、選んだ回戦の試合を結果カード（resultCards.js）で縦に並べる。初めに開く回戦は「試合待ちがある最初の回戦」（roundView.js の defaultRoundKey と同じ考え方）。休みの選手がいる回戦は、カードの下に「休み：○○」を1行で出す。
- 回戦のタブとカードの部品は roundView.js を総当たりでも使えるように一般化する。トーナメント（R1, R2 など）と総当たり（1, 2 など）では回戦のキーやデータ構造が違うので、回戦のキーと表示名を外から渡せる形に抽象化する。総当たり用に同じ見た目の部品を別に作らない。回戦の選び方など画面に依存しない判定は単体テストを足す。
- 「対戦表で見る」では、対戦表の上に「選手を選ぶ」欄を置き、選んだ選手の行だけを縦のリスト（対戦相手・○×△とスコア・状態）で出す。初期値は「すべて」で、そのときは今の横スクロールの対戦表を出す。自分の試合（F1）で名前を選んでいれば、その名前を初期値にする。
- 「回戦ごと」を出しているときは、下の「試合結果一覧」を折りたたみ（details 要素、見出しに「66試合」の件数）にし、初期状態は閉じる。絞り込み（D9）は一覧の中に残す。
- 結果を保存したあとは、その試合のカードを今と同じ方法で1.5秒強調する。その回戦の試合がすべて終わっても、回戦のタブは自動で切り替えない（入力中に画面が動かないようにするため）。
- CSV・PNG出力と印刷は変えない。
確認：12人・2卓・引き分けありの総当たりで、幅390pxのページの高さが約2,000px以下になること、横スクロールが出ないこと、奇数人数（11人）で「休み」が出ることを、E2E とスクリーンショットで確かめる。
```

### N5 進行状況の欄を「卓ごと」にまとめる（中・中）（実装済み）

