# N14 PNG 出力のフォントを画面とそろえる — 方法の比較

> 追記: この報告の案Bで実装しました（`PLAN.md` D58）。以下は、実装の前に出した報告のままです（「アプリのコードは変えていません」は、報告を出した時点の状態）。

`docs/ui-plan-2.md` の N14 の依頼どおり、実装の前に方法を比べた報告です。**アプリのコードは変えていません**。比べるために試作を作って測りましたが、リポジトリには入れていません（結果だけをここに記録します）。

## 結論（先に）

**おすすめは案B「SVG を読み取って canvas に直接描く」です。**

- 既存の SVG を作る処理（`bracketSvg`・`tableSvg`）を**そのまま使い回せます**（変えるのは、SVG を PNG にする最後の部分だけ）
- `file://`・`https://`・Electron の**すべてで動きます**。実行時の依存も増えません
- PNG の出力は**現状と同じか速い**（12人 約0.16秒・64人 約0.3秒・128人 約0.37秒。現状は 0.11・0.38・0.78 秒）
- コードの変更量は**約60〜100行**（新しい描画部分＋差し替え）
- 案A（フォントを SVG に埋め込む）は、ブラウザで `file://` を直接開くと**動きません**。出力に1〜2秒かかり、SVG が約1MBになります

- `docs/screenshots/n14/bracket12-a.png`: 案A（IBM Plex Sans JP）
- `docs/screenshots/n14/bracket12-b.png`: 案B（IBM Plex Sans JP）
- 総当たり表（表）も同じ組み合わせ: `matrix12-current.png`・`matrix12-a.png`・`matrix12-b.png`

案A と案B は、どちらも IBM Plex Sans JP で、画面の表と同じ字形です。2つの違いは、案B のほうが文字の位置が**約1px 下**に出ることだけです（canvas の `textBaseline = 'middle'` と、SVG の `dominant-baseline="central"` の基準の差。実装では、文字の高さの分だけ y を補正して、そろえます）。

## 案B を選ぶ理由

1. **使い回し**: PNG 用の SVG を作る処理（文字幅の計測を含む）は、画面と同じ設定（`FONT_FAMILY`・`measureText`）にでき、`svg.js` の中身を変えずに済みます。画面と PNG で表の配置が一致します（今は、端末のフォントで測るため、配置が少し違う）
2. **どの環境でも同じ**: 画面が IBM Plex を表示できる環境なら、PNG も同じフォントで描けます（ページに読み込んだフォントを使うだけ）。`file://`・Electron でも、新しいファイルの読み込みや `fetch` が要りません
3. **速い・軽い**: フォントを埋め込まないので、SVG が大きくならず、変換が速い
4. **実行時の依存が増えない**

## 案B の注意点（実装するなら、先に決めておくこと）

- **描ける SVG の要素は限られる**: 今の PNG 用の SVG は `rect`・`line`・`text` だけです。要素が増えたとき（`path` など）に、静かに描き漏れて表示が崩れるのを防ぐため、読み取りの処理は、未対応の要素や属性（`transform`・`opacity` など）を見つけたらエラーにします。あわせて単体テストで「PNG 用の SVG に使う要素の種類」を固定します
- **フォントが読み込めなかったとき**: `document.fonts.load` が失敗しても、canvas は指定した後ろのフォント（端末のフォント）で描くので、現状と同じ見た目になります（失敗しない）。読み込みが終わらない場合に備え、待つのは長くても1秒ほどにして、過ぎたら端末のフォントで描きます。画面と同じフォントで描けたかどうかは、利用者には出さなくてよい
- **`PLAN.md` D48 の注記を直す**: 「画面と PNG でフォントが違うことを知らせる」文言と、`pngOptions`・`EXPORT_FONT_FAMILY` が不要になります（`CLAUDE.md` の「PNG 出力だけは端末のフォント」の1文も直す）
- **canvas の上限**: 今と同じ（約16000px 角を超えないよう倍率を下げる処理をそのまま使う）。128人（4,408×9,440px）でも動くことを確認しました
- **確かめること**: 単体テスト（描く要素の種類・文字の位置の補正）、E2E（PNG の出力が成功し、IBM Plex の幅で作られる＝出力の幅が画面の SVG と一致する）、`npm run test:electron`
